- **`Capability::Override("*")` no longer reaches the app's modules** (zgx-script): replacing a module runs as the app's own code, so it takes a grant that says so. `Capability::OverrideElement(target)` is for `ui.contribute { replace }` and `ui.filter`, `Capability::OverrideModule("@app/…")` for `ui.override`, each with `"*"` for any. The older `Override` reads by what it names, so `Override("#x")`, `Override("*")` for elements and `Override("@app/x")` work as before. *Migrate:* a plugin given `Override("*")` that overrides modules needs `OverrideModule("*")`; in `zgx.json`, `override-module:*` beside `override:*`.
- **A plugin offers only slots of its own** (zgx-script): `ui.slot(name)` in a plugin's VM takes `<plugin>.…`, so a plugin can't pose as the app's slot or another's and take what is contributed there. *Migrate:* name a plugin's slot `<plugin>.name`, and have what contributes to it say so. The app's own scripts name theirs as before.
- **A plugin's shortcut has a modifier** (zgx-script): `ui.command { key = "k" }` from a plugin (no modifier, or Shift alone on a character) would take that key from every field, page and terminal, and is now an error; one a state or function says is dropped as it reads so, in `ScriptHost::dropped_shortcuts`. *Migrate:* give it a modifier, or grant the plugin `Capability::Named("zgx.command.bare_keys")`.
