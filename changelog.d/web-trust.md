- **Certificate errors and credentials are the app's** (zgx, zgx-desktop): `WebView::set_certificate_handler` hears each certificate error a page meets (its host, the error, and `can_proceed`: whether the engine can load past it for that one load alone), and `WebView::set_auth_handler` each credentials challenge (host, realm, scheme), answered with a user name and password, stored nowhere (the engine may reuse them for that server for the session, as browsers do). Neither is ever answered for the app: with no handler, or a responder dropped unanswered, the load is cancelled and the page gets the server's refusal. WebView2 proceeds for one load, clearing its session-long allow as it's given; WKWebView, WebKitGTK and Ladybird can't hold a proceed to one load, so they report the error and cancel. WebView2 answers Basic credentials; WKWebView and WebKitGTK also Digest, NTLM and Negotiate; Ladybird doesn't yet ask.
