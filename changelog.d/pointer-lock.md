- **A node can lock the pointer, as the DOM's Pointer Lock** (zgx, zgx-desktop, zgx-script): a game's look about, a 3D view's orbit. `InputDispatcher::lock_pointer(scene, node)` (`NodeHandle::lock_pointer`, `el:lock_pointer()` in Luau) holds the pointer for the node: hidden and kept in place (winit's `CursorGrabMode::Locked`; `Confined` on X11, which has no lock), every press, release and wheel to the node wherever it is, and the mouse's raw motion as the new `InputEvent::PointerMotion { dx, dy }` (Luau: `on_pointer_move`'s `dx`, `dy`, with `locked = true`). Only within a second of a press, a release or a key, so nothing takes the pointer unasked; Escape always lets it go (and goes nowhere else), as do the window losing focus, the node leaving or being disabled, another node locking it and `unlock_pointer`. The node hears `InputEvent::PointerLockChange` (Luau: `on_pointer_lock(locked)`), and the pointer comes back where it locked. Raw device events are listened for only while a pointer is locked, so other windows still read none. `on_pointer_move` also tells every move its `dx`, `dy` from the last, as the DOM's `movementX`.
