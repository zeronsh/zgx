---
section: performance
---
- **A Luau app's modules compile on a worker while its window is made** (zgx-script, zgx-run): `zgx-run` calls `zgx_script::compile_ahead(script, packages)` before the app's window, the GPU and AppKit are set up. A worker compiles the script and what it reaches by `require` with a string literal (`.luaurc` aliases and lent packages resolved as `require` does; no tests, type files or unused modules; files up to 1 MB). The first load's `require`s then find their bytecode compiled, rather than compiling each on the main thread. It is compiled in memory from the text and used only for the very bytes `require` reads; no bytecode is written to or read from a file, and nothing waits for the worker. What the load didn't use is let go as it ends. An app hosting its own `ScriptHost` calls `compile_ahead` itself, first thing in `main`. A 170-module app (466 KB): main-thread compile 7.3 → 0.5 ms, its build 15.7 → 7.9 ms (macOS, medians of 12), peak memory no higher. Hosts that don't call it pay one atomic load per `require`.
