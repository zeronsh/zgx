- **What GPU views' painters ask beyond drawing is zgx-gpu's `view-features` feature** (zgx-gpu, zgx-desktop, zgx-run): ray queries (`request_ray_queries`, `ray_queries_status`), the optional device features views use (`request_view_features`, `view_features_decided`), packed-float targets, a painter resting as its window idles or its last box goes (`Viewport::rest`), and one instant a frame for every view. zgx-3d turns it on; zgx-desktop forwards it (`view-features`) for its re-export, zgx-run's `scene3d` with it. Off, a UI app's binary is as it was before them, byte for byte in its code and constants; a runner without 3D accepts a `zgx.json`'s `gpu` key and ignores it. `WGPU_FORCE_FALLBACK_ADAPTER` isn't read on macOS, where there is no software adapter for Metal (it made the renderer fail to start).
