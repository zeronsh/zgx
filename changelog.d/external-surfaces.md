- **Another program's frames show as an element, its input forwarded** (zgx-surface, zgx-desktop, zgx-script): a game, an emulator or a renderer on a wgpu of its own draws into buffers zgx shares with it, and zgx composites them as any image (rounded, clipped, faded, popovers over them). On Linux the buffers are Vulkan images on zgx's own GPU, exported as opaque file descriptors and imported by a client on the same device (matched by UUID), so no CPU copies a pixel; shared memory is the fallback everywhere. The new crate `zgx-surface` holds the protocol and the client (no wgpu in its core; `wgpu29` turns buffers into wgpu 29 textures, and a client on another wgpu copies that module). Rust: `zgx_desktop::surface::{App, surface}` (the desktop host's `surfaces` feature). Luau: `ui.app(id, { command, args, cwd, env, on_exit })` starts a program, no shell, as a session kept across reloads, and `ui.surface { app = a }` shows it (zgx-script's `apps` feature, which zgx-run has). Keys go by physical code, text apart, the pointer in the surface's pixels, and the program can lock the pointer just after a press. A plugin needs the new `apps` grant (`Capability::Apps`); the host decides exactly what runs (`ScriptHost::vet_apps` takes the spec asked for and returns the one to start), asked again whenever a script reaches a running session; the app's own VM asks its guard (`GuardKind::App`). See [External surfaces](docs/external-surfaces.md).
