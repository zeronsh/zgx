- **`ZGX_RELOAD=partial`: a hot reload runs again only what a save changed** (zgx-script, opt-in while it is proven on real apps): while a host watches its files, a save keeps the app's VM and runs again the modules it changed, what requires them, and the app's script; the other modules keep the values they returned and what their top levels made, and what a module running again made at its top level goes first (#1369). Everything loads again, as before, when keeping couldn't be right: plugins are loaded, a module running again sets a global or starts a task, animation, `on_open` handler, actions or router at its top level, a module kept declares a command, window, contribution, override or `on_mount` there, every module changed (a template swapped whole), or the last reload failed partway. A failed partial reload leaves the last load running as it was. `zgx inspect reloads` says which path each reload took and why; without the variable every reload loads everything and says what it would have kept. It lists the reloads a host asks for (`ScriptHost::reload`) too, a watched file whose bytes a reload already read no longer reloads the scripts again, and a global zgx makes on first read (`anime`) no longer counts as the module setting it.
