- **A script lists the controls on screen, presses one and reads its text** (zgx, zgx-script): `ui.controls { limit? }` returns the active window's visible accessible nodes as the accessibility tree has them, in document order with popups, menus and modals last, each `{ role, name, x, y, w, h, disabled, selected, checked, expanded, pressed, haspopup, focused, handle }` in window points, a menu's or list box's scroll view adding `scroll_offset`, `scroll_range`, `at_start` and `at_end` (a plain group, a text, a scroll view or a table's rows are left out, hidden nodes and ones with no box too). `ui.press(handle)` presses and releases the primary button at the middle of the control a handle names, as `zgx inspect click` does, through the window's input; a stale, hidden or covered handle presses nothing and gives false, as does a press made from inside an input handler. `ui.text_of(handle, cap?)` is the text the control shows, a word apart, at most `cap` (400) characters. Nothing is made until a script names one of them. A script under a host's `guard` reaches only its own view with them, host views it shows left out. A Rust host gives the window with `ScriptHost::window_controls(&ui)` (`zgx-run` does); a plugin gets an error. `el:scroll_info()` gives a scroll view's or list's `{ offset, range, at_start, at_end }`, nil for anything else.
