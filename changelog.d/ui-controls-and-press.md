- **A script lists the controls on screen and presses one** (zgx, zgx-script): `ui.controls { limit? }` returns the active window's visible accessible nodes as the accessibility tree has them, in document order with popups, menus and modals last, each `{ role, name, x, y, w, h, disabled, selected, expanded, focused, handle }` in window points (a plain group, a text, a scroll view or a table's rows are left out, hidden nodes and ones with no box too), and `ui.press(handle)` presses and releases the primary button at the middle of the control a handle names, as `zgx inspect click` does, through the window's input. Nothing is built until `ui.controls` is called. A stale, hidden or covered handle presses nothing and gives false, as does a press made from inside an input handler. A Rust host gives the window with `ScriptHost::window_controls(&ui)` (`zgx-run` does); a plugin gets an error. New: `NodeId::to_bits`/`from_bits` and `Ui::window_is_active`.
