- **A copy can carry types of the app's own, and a web page's paste reads them** (zgx-script, zgx-desktop, zgx-dom): a selectable region's `on_copy` may return `types = { [mime] = text }` beside `text` and `html`, and `ui.clipboard.write { text, html?, types? }` writes the same. Both go in one change of the clipboard. `ui.clipboard.read_type(mime)` reads a type back. The types go where Chromium keeps a page's own types (its web custom data: `org.chromium.web-custom-data` on macOS, `Chromium Web Custom MIME Data Format` on Windows, `chromium/x-web-custom-data` on X11 and Wayland). So a page's `getData("application/x-…")` in Chrome, Edge or an Electron app pastes what a zgx app copied, and a zgx app reads what such a page's copy set: a chat answer's live citations pasted into a note. Rust hosts get `Platform::set_clipboard_typed`, `clipboard_types` and `clipboard_typed`. The memory clipboard (`ZGX_CLIPBOARD=memory`) and the test desktop keep the types. A copy without types takes the path it always did. zgx-desktop's clipboard now builds on `zgx-arboard`, arboard 3.6.1 with one write of text, HTML and formats of the caller's (`vendor/arboard/ZGX_PATCH.md`).
