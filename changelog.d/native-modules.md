- **Native modules** (zgx-script's `modules` feature, the new `zgx-module` crate): an app's own Rust built apart from zgx as a library and loaded as the app starts (`ScriptHost::load_module`). A module is a `mod` marked `#[zgx_module::module]` whose `#[export]` functions take Rust types (`&str`, numbers, `Option`, lists, maps, structs deriving `Record`); scripts call them as members of the module's table, `ui.module("words").count(text)`, typed in the editor from the module's manifest by `zgx types`, or by name with `ui.call_sync` and `ui.action`, untyped. A wrong argument is an error raised in the script naming the function, the module and the argument. A module links `zgx-module` and nothing of zgx, so a change to a module rebuilds that module alone, and it reads the runtime's values where they are, with no copy: a call into a loaded module costs 14 instructions more than the same function linked in. `zgx_module.h` is the same interface for C. Only the app's Rust loads one: no script or plugin can. [The guide](docs/modules.md); [the design](docs/design/runtime.md).
