# 3D scenes in Rust

`zgx-3d` is a retained 3D world shown in any box: meshes in metallic-roughness materials, lights, a camera, and glTF models with their textures, animations and skins. A world draws a frame only when it changes, so a still scene costs nothing, and its pipelines and buffers are made with its first frame. In Luau the same world is [`ui.scene3d`](reference/3d.md).

```toml
[dependencies]
zgx-3d = { version = "0.1", features = ["gltf"] } # gltf: Model, and PNG and JPEG textures
```

## A world

A `World` holds objects (`Object::mesh`, or `Object::group` to place several as one), lights and a camera. Its `view()` is a [GPU view](gpu-views.md), so the box showing it clips, rounds, fades and hit tests like any other.

```rust,no_run
use zgx::compose::prelude::*;
use zgx_3d::*;

let world = World::new();
world.set_background(Some(0x10141b));
let group = world.add(Object::group());
let cube = world.add(Object::mesh(Geometry::cuboid(1., 1., 1.), Material::rgb(0x4a90e2).with(0., 0.35)).child_of(group));
world.add(Object::mesh(Geometry::sphere(0.35, 32), Material::rgb(0xd9a441).with(1., 0.3)).at([1.3, 0., 0.]).child_of(group));
world.add_light(Light::Directional { direction: vec3(-0.5, -1., -0.4), color: [1., 1., 1.], intensity: 2.5 });
world.set_camera(Camera::looking_at([0., 1.5, 4.], [0., 0., 0.]));

let view = gpu_view("A cube and a sphere", world.view()).w_full().h(320.);

// One change, one frame:
world.update(cube, |object| object.transform.rotation = Quat::from_euler(0., 0.5, 0.));
```

`Geometry` has `cuboid`, `sphere`, `plane`, `cylinder`, `cone` and `torus`, and `Geometry::new(vertices, indices)` takes your own triangles. Each geometry's meshes draw in one instanced call.

## Camera controls

`OrbitControls` answers a view's input as a model viewer does: drag to turn, right-, middle- or Shift-drag to pan, scroll or pinch to zoom (Shift-scroll pans), and, focused, the arrow keys turn (pan with Shift), `+` and `-` zoom and Home comes back. `zoom`, `pan` and `inertia` are fields to turn off. Hand it each event; its `Answer` says what happened.

```rust,no_run
use std::{cell::RefCell, rc::Rc, time::Instant};
use zgx::{compose::prelude::*, input::InputEvent};
use zgx_3d::*;

let world = World::new();
let controls = Rc::new(RefCell::new(OrbitControls::new(Orbit { distance: 4., ..Orbit::default() })));
world.set_camera(controls.borrow().orbit.camera(world.camera()));

let view = gpu_view("A model", world.view()).w_full().h_full().focusable(true).on_event({
    let world = world.clone();
    move |event| {
        let modifiers = match &event.event {
            InputEvent::KeyDown { modifiers, .. } => *modifiers,
            _ => event.pointer_modifiers(),
        };
        let mut controls = controls.borrow_mut();
        let answer = controls.handle(&event.event, modifiers, Instant::now());
        if answer.moved {
            world.set_camera(controls.orbit.camera(world.camera()));
        }
        if answer.taken {
            event.prevent_default();
        }
    }
});
```

`answer.coasting` says a flick is coasting on: call `coast(seconds)` a frame at a time until it returns `false`, setting the camera each time ([the `model` example](../crates/zgx-3d/examples/model.rs) does). Set `inertia = false` for reduced motion. `Orbit` alone is the arithmetic: `drag`, `zoom`, `pan` and `camera(base)`.

## Models

With the `gltf` feature, `Model::from_bytes` reads a `.glb` or a `.gltf` whose buffers are inline, and `Model::from_bytes_with` reads one whose buffers sit beside it. `World::add_model` adds it as one group to place, turn and scale. A model brings its default scene's nodes, its meshes (with smooth normals where it has none), its materials and their base colour, metal-roughness, normal, emission and occlusion textures, where those sit (a second set of texture coordinates, samplers' wrapping, `KHR_texture_transform`), its vertices' colours, its skins and its morph targets, and its lights (`KHR_lights_punctual`), each following its node, and its glass (`KHR_materials_transmission`, `KHR_materials_ior`, `KHR_materials_volume`, with their transmission and thickness textures) and clear coats (`KHR_materials_clearcoat`, with its coat, roughness and normal textures; `World::set_clearcoat` gives a mesh one) and how its dielectrics reflect (`KHR_materials_specular`'s factor and colour and `KHR_materials_ior`'s index; `World::set_specular`). `Placed::cameras(&world)` gives its cameras where its nodes are, for `World::set_camera`.

To play its animations, place it with `World::place_model`, which keeps its nodes' objects, and give it an animator. `Model::clips` lists its clips (`clip(name)` finds one). An animator plays them by the world's frames, at each frame's time (never the wall clock, so a video renders the same poses each time): while a clip plays the world draws by itself, and paused (`set_animator_speed(id, 0.)`), stopped or done it draws nothing.

```rust,no_run
use zgx_3d::*;

fn play(world: &World, bytes: &[u8]) -> Result<(), Box<dyn std::error::Error>> {
    let model = Model::from_bytes(bytes)?;
    let placed = world.place_model(&model);
    let animator = world.add_animator(&placed);
    let (Some(walk), Some(wave)) = (model.clip("Walk"), model.clip("Wave")) else { return Ok(()) };
    world.play(animator, walk, Play::new())?;
    // Later: wave with the upper body over the walk, fading in over a fifth of a second.
    let spine = placed.node(3).expect("the spine's node");
    world.set_layer(animator, 1, Layer::new().mask(Mask::new().below(spine, 1.)))?;
    world.play(animator, wave, Play::new().layer(1).fade(0.2).once())?;
    Ok(())
}
```

- **Layers** are counted from 0, the lowest. Each has a weight, a `Mask` (nodes, or a node and all under it with `Mask::below`, each taking 0 to 1 of the layer) and a blend: `Layer::new()` takes the place of the layers under it by its weight, `Layer::additive()` adds how far its clip has moved from its first key (a lean, a breath).
- **Morph weights** a clip moves (a face's, a muscle's) play through the same layers, crossfades, masks (by the node holding the meshes) and additive blends as places do, each weight a number; a target no clip moves keeps the weight it had when the animator was added.
- **Within a layer** a clip played with `fade(seconds)` crossfades from what played there; `World::stop(id, layer, fade)` fades a layer out.
- **`Play`** says the layer, the fade, the `speed` (negative plays backwards), `once()` (held at its end; looping otherwise) and `from(seconds)`.
- **Events**: `clip.with_event(0.4, "step")` is reported each time the clip passes 0.4 s, in `World::animator_update(id).events`.
- **Root motion**: `World::set_root_motion(id, Some(RootMotion::new(hips)))` takes a node's motion along the model's ground out of its pose and gives it in `animator_update(id).moved` (`.vertical()` takes its rise too, `.turn()` its turn about up, in `turned`), so a walk moves the character rather than its hips away from it. It's blended as the pose is, measured in the model's frame (a z-up file's armature turned included), and `.apply_to(placed.root)` moves and turns that object by it, along its facing, in the same frame.
- **IK**: `World::set_ik(id, hook)` calls `hook` with the pose each frame it's posed, after the layers blend it and root motion is taken out, before it's drawn (skins follow). `ik::two_bone(pose, [shoulder, elbow, wrist], target, Some(pole), 1.)` bends an arm or a leg to reach a point in the world, its middle joint toward the pole; `ik::look_at(pose, head, vec3(0., 0., 1.), target, 1., 1.2)` turns a node's axis toward a point, at most 1.2 radians; `Pose::local`, `set_local` and `world` do the rest by hand. The hook runs inside the frame: it mustn't call the world, and shares what it reads (a target) by an `Rc<Cell<_>>`. A target moved while nothing plays waits for `World::repose(id)`.
- **While nothing shows** (a layer at weight 0, masked to nothing, or a clip moving no node of the model) the world rests: its clips' times stand still until a frame shows them again, then go on by the whole time between, so they come back in step. A looping clip's events and root motion for that stretch come out as at most one loop's worth, not the stretch's.
- **Crowds**: animators each playing one clip alone (one layer, wholly, no mask, fade, root motion, IK or morphs) at the same time, as a crowd started together does, share one sampled pose a frame: the first poses it, the rest copy the places its channels move (`SCENE=anim ANIMATOR=lockstep` in `world_bench`: 9% of the frame less than the same crowd each at its own time).
- A frame finds each clip's key times once for all its channels, from where the last frame left them, and writes only the nodes whose places changed. A gap between frames longer than a quarter second (the view hidden) is taken as a quarter second: an animation goes on where it was.

What it costs, and how it was measured against Bevy's on the same clip (about 560 instructions a joint a frame to sample and pose, against `Placed::pose`'s 1,820; Bevy 0.19.1 spends about 4,490 a joint a frame playing): `comparisons/3d/README.md`, "Animation", with both arms to run again.

**Clips made in code** play the same way: `Clip::builder("Wave")` takes channels by node index (`translation`, `rotation`, `scale`, `weight`), each `Keys::step`, `Keys::linear` or `Keys::cubic` (a key's in-tangent, value and out-tangent), and `build()` checks them: a channel without keys, a time or value that isn't a number, times falling, a value missing, or more than `MAX_CLIP_KEYS` in all is a `ClipError`, never a panic. Objects made in code become nodes to play them on with `Placed::new(root, nodes)` (and `with_meshes(node, meshes)` for those taking a node's morph weights).

```rust,no_run
use zgx_3d::*;

fn bob(world: &World) -> Result<(), Box<dyn std::error::Error>> {
    let root = world.add(Object::group());
    let buoy = world.add(Object::mesh(Geometry::sphere(0.3, 16), Material::rgb(0xe05a2b)).child_of(root));
    let clip = Clip::builder("Bob")
        .translation(0, Keys::linear(vec![0., 1., 2.], vec![[0., 0., 0.], [0., 0.2, 0.], [0., 0., 0.]]))
        .build()?;
    let animator = world.add_animator(&Placed::new(root, vec![buoy]));
    world.play(animator, &clip, Play::new())?;
    Ok(())
}
```

`Placed::pose` poses one clip at any time by hand, drawing a frame only if something moved.

`cargo run --release -p zgx-3d --features gltf --example model -- FILE` shows a file and plays its first clip.

## Textures

`Texture::from_rgba8` takes pixels and `Texture::decode` a PNG or JPEG. `World::set_texture(id, Some(texture))` gives a mesh its base colour, and `World::set_map(id, map, Some(texture))` the rest: `Map::MetalRoughness`, `Map::Normal`, `Map::Emission` and `Map::Occlusion`, and for a mesh light passes through, `Map::Transmission` (how much passes, red) and `Map::Thickness` (how deep, green), and for a coated one `Map::Clearcoat` (how much coat, red), `Map::ClearcoatRoughness` (how rough, green) and `Map::ClearcoatNormal` (which way the coat faces), each read at its first texture coordinates as they are. A normal map's frame comes from the screen's derivatives, so meshes need no tangents. A texture decoded from a file holds the file, and its decoded pixels only until a renderer has uploaded them. A scene without textures binds none.

Maps read from files load off the frame: decoded, their smaller levels made and put on the GPU by threads of zgx-3d's own (the machine's cores less two, at most 8, parked while there is nothing to load). The first frame shows at once; a mesh whose map hasn't arrived draws in its material's own colours (white times its colour where a base colour map will go, flat where a normal map will), and its world keeps drawing frames until every map is in, then rests. `World::loading()` says whether any is still on its way, so an app can hold a curtain or a progress bar over the scene. Maps of 128² or less, maps given as pixels, and every map of a frame drawn whole (a video's) load in the frame that first draws them. Worlds take turns on those threads, so one scene's hundreds of maps don't hold up another's first; where the system won't start a thread, maps load in the frame.

## Skins

`Geometry::with_skin(joints, weights)` gives each vertex up to four joints, and `World::set_skin(id, Some(skin))` binds a mesh's object to a `Skin::new(joints, inverse_binds)`: objects as joints, up to `MAX_JOINTS` (256). The GPU places each vertex by its joints' matrices, so moving the joint objects bends the mesh, and its shadow and picking follow the pose. glTF models bring theirs.

```rust,no_run
use zgx_3d::*;

fn bend(world: &World) -> Result<(), &'static str> {
    let root = world.add(Object::group());
    let tip = world.add(Object::group().at([0., 1., 0.]).child_of(root));
    let bar = Geometry::cuboid(0.2, 2., 0.2);
    // Each vertex follows the joint at its end of the bar.
    let (joints, weights): (Vec<_>, Vec<_>) = bar
        .vertices()
        .iter()
        .map(|v| ([if v.position[1] > 0. { 1u16 } else { 0 }, 0, 0, 0], [1., 0., 0., 0.]))
        .unzip();
    let mesh = world.add(Object::mesh(bar.with_skin(joints, weights)?, Material::rgb(0xd9a441)));
    let inverse_binds = vec![Mat4::IDENTITY, Mat4::from_transform(vec3(0., -1., 0.), Quat::IDENTITY, Vec3::ONE)];
    world.set_skin(mesh, Some(Skin::new(vec![root, tip], inverse_binds)?));
    // Turning the tip's joint bends the bar:
    world.update(tip, |object| object.transform.rotation = Quat::from_euler(0.6, 0., 0.));
    Ok(())
}
```

## Light

`World::set_environment(Some(Environment::studio()))` lights every surface from all around, its reflections sharp in polished metal and blurred in rough. The studio is built in; `Environment::decode_hdr` reads a Radiance `.hdr` image (equirectangular), and `from_equirect` and `from_cube` take linear RGB. `intensity` brightens one and `rotated` turns it. Making one takes 11–16 ms, so do it off the main thread; the studio is made once for the app.

With the `lighting` feature, a world shades every point and spot light, not only the eight nearest the camera's target: past eight (or with `World::set_clustered_lights(true)`) its view is cut into 16 by 9 tiles and 24 slices of depth, each light is listed in the clusters its reach touches, and each pixel shades with its own cluster's lights alone, so hundreds of lights cost about what the few reaching each pixel do. The lists are made on the CPU, and made again only when a light, the camera or the view's size changes: 256 lights seen by a moving camera cost about 0.4 M instructions a frame, binned and uploaded. A device without storage buffers in its shaders (some GL) shades the eight nearest instead.

```rust,no_run
use zgx_3d::*;

let world = World::new();
for i in 0..256 {
    let (x, z) = ((i % 16) as f32 * 2. - 15., (i / 16) as f32 * 2. - 15.);
    world.add_light(Light::Point { position: vec3(x, 0.5, z), color: [1., 0.8, 0.6], intensity: 2., range: 1.5 });
}
```

Lights can be given in physical units: `Light::point(position)` and `Light::spot(position, direction)` make a `PointLight` whose brightness is in candela (`candela`) or lumens (`lumens`: a point's or a spot's is `lumens / 4π` candela, so narrowing a spot keeps how bright it is where it shines), with a colour, a `range` it falls smoothly to nothing at, a `cone` for a spot, and a `radius`: a light as big as a bulb falls off from its surface, so it lights what it nearly touches without a burning point, and its highlights on shiny surfaces are as wide as it looks. `World::add_point_light` adds one. `Light::Point`'s `intensity` is in candela too, so a world written before means the same. A light with a radius shades through clusters.

```rust,ignore
// With the `lighting` feature.
use zgx_3d::*;

let world = World::new();
world.add_point_light(Light::point([0., 2.4, 0.]).lumens(800.).color([1., 0.9, 0.8]).range(8.).radius(0.04));
world.add_point_light(Light::spot([2., 3., 1.], [-0.5, -1., -0.2]).lumens(4000.).cone(0.3, 0.5));
```

`World::set_shadows(true)` has the sun, the first directional light, cast soft shadows from opaque meshes. It costs a 2048 by 2048 depth map (16 MB) and a depth pass drawn again only when meshes or the sun move, not the camera.

With the `lighting` feature, `World::set_cascades(Some(Cascades::new(4)))` cuts the sun's shadow into up to four cascades: the view's depth up to `distance` (100 m by default) in slices, nearer ones smaller, each shadowed by a map of its own `size` texels square (2048 by default, 16-bit depth: 32 MB for four, in place of the single map's 16 MB), so shadows near the camera are sharp however far the scene reaches. Each cascade holds its slice's bounding sphere and moves by whole texels of its map, so shadow edges hold still under a moving camera. A cascade's map is drawn again only when it moved, the sun did, or a caster inside it did, each cascade drawing only the casters inside it; the nearest follows a moving camera every frame, the others one a frame between them, so a turning camera costs about two cascades' passes a frame. Past the last cascade nothing is in shadow.

```rust,ignore
// With the `lighting` feature.
use zgx_3d::*;

let world = World::new();
world.set_shadows(true);
world.set_cascades(Some(Cascades::new(4).distance(60.)));
```

`World::set_tone_mapping` says how lit colours reach the display's range: `ToneMapping::Neutral` (the default) keeps colours as the material says and rolls highlights off, `Aces` is the filmic curve, and `Linear` clamps. `World::set_exposure(stops)` doubles the light for each stop.

`World::set_samples(1)` draws hard edges at a quarter of the colour and depth memory; the default, 4, multisamples and smooths highlights on fine curves too, for about 1% more GPU work.

```rust,no_run
use zgx_3d::*;

let world = World::new();
world.set_environment(Some(Environment::studio().intensity(0.8).rotated(0.5)));
world.set_shadows(true);
world.set_tone_mapping(ToneMapping::Aces);
world.set_exposure(0.5);
```

## What the device can do

`World::caps()` says what the device the view draws with can do, once a frame has been drawn (`None` before: the device is the window's). `Tier::A` (Metal, Direct3D 12, Vulkan) runs compute, binds storage buffers and textures in every stage and draws indirectly; `Tier::B` (GL) is taken to do none of those. `Caps` also says whether timestamps can be taken, which compressed formats it samples, whether shaders can trace rays (`ray_queries`) or index arrays of textures, and its compute limits. It's read again when the view moves to another device.

```rust,no_run
use zgx_3d::*;

fn plan(world: &World) {
    match world.caps() {
        Some(caps) if caps.compute => { /* GPU particles, compute passes */ }
        Some(_) => { /* tier B: CPU fallbacks */ }
        None => { /* not drawn yet: ask again after the first frame */ }
    }
}
```

## GPU data and compute

With the `compute` feature, a world holds buffers and textures of the app's on the device and runs WGSL compute passes over them, for simulations, generated textures, or anything a material or emitter then reads.

`World::add_buffer` makes a `GpuBuffer` (`BufferDesc::storage::<T>(count)`, `bytes(n)` or `from_slice(&values)`), and `World::add_texture` a `GpuTexture` (`TextureDesc::storage(width, height, Format::Rgba16Float)`), zeroed. The handle owns it: the world counts its bytes in `World::memory()` while it (or a pass binding it) lives, refuses more than its cap (`set_memory_cap`, 256 MiB to begin with), and lets the device's copy go when the last clone drops. `buffer.write(offset, &values)` lands before the next frame's passes.

`World::add_compute` adds a `Compute`: the shader, the resources it binds by the names it gives them and how (`Access::Read`, `Write` when the pass writes all of it, or `ReadWrite`), how many workgroups (`dispatch`) or invocations (`threads`), and when: `every_frame()`, `at_rate(per_second)` of frame time, or `on_demand()` (once when added, again on each `World::run_compute`). A uniform the shader names `frame` holds the frame's `time`, `delta` and `index`, and a `sampler` is a linear one.

```rust,ignore
let waves = world.add_buffer(BufferDesc::storage::<[f32; 4]>(256 * 256))?;
let height = world.add_texture(TextureDesc::storage(256, 256, Format::Rgba16Float))?;
let pass = world.add_compute(
    Compute::new(include_str!("waves.wgsl"))
        .buffer("waves", &waves, Access::ReadWrite)
        .texture("height", &height, Access::Write)
        .threads([256, 256, 1])
        .every_frame(),
)?;
let read = waves.read(0..64); // resolves 1 to 3 frames later
```

The shader is parsed and checked when the pass is added: a mistake comes back as `ComputeError::Shader` at the shader's own lines, and bindings that don't match the shader's declarations, workgroups past the limits every tier A device has, and an order that can't hold are refused there too. It's compiled on a thread of its own, so no frame waits for it; `World::compute_status` says when it's ready. Where the device runs no compute (`caps().compute` is false: GL), `add_compute` returns `ComputeError::Unsupported`.

Passes run before the frame is drawn, or after it (`.at(Point::AfterFrame)`), in the order added, except that a pass writing a resource whole runs before passes added earlier that read it. A world with an enabled every-frame pass keeps drawing; a rated pass keeps it drawing only while it's due within two frames, and an on-demand one draws the frame it runs in; a world whose passes aren't due draws nothing. Until zgx can wake a view at a given time, a rated pass slower than the display runs with the first frame drawn, for any reason, at or after its due time.

**What a pass may cost.** The device is every window's, and a shader's loops can't be bounded by reading it: WGSL has no way to say a loop ends, and zgx-3d doesn't rewrite shaders. So passes are held where they run, by `World::set_compute_budget(ComputeBudget { .. })`:
- `invocations`, all a frame's passes may run (2^26 to begin with): a pass with more alone is refused by `add_compute`; passes past it in a frame wait for the next, those that waited going first then;
- `gpu_ms`, the GPU time a pass may take (8 ms), measured where the device has timestamps (`caps().timestamps`); a pass over it in `frames` (3) of its last 8 timed frames is turned off, its status `ComputeStatus::OverBudget`.

Timing only sees passes that finish, so it can't stop a shader that never does. A pass marked `.sandboxed(owner)` (code the app doesn't vouch for: a plugin's, named by `owner`) is therefore checked and bounded before it runs (`shader_sandbox`), held to stricter time budgets (`sandboxed_gpu_ms`, 1 ms; `owner_gpu_ms`, 2 ms for all of one owner's passes a frame), and refused (`ComputeError::Untimed`) on a device without timestamps. **A host must not grant compute to code it doesn't trust on a device that can't time it.** zgx's shared device asks for no timestamps yet, so for now sandboxed passes are refused everywhere.

### What a sandboxed shader can spend, and what bounds it

| Resource | Bound |
| --- | --- |
| GPU time in loops, per invocation | Every loop counts against one counter for the invocation (all loops, nested and in called functions, together); past its cap each loop breaks. WGSL has no recursion, so loops are the only statements that repeat. |
| GPU time without loops, per invocation | A static cost over the shader, with calls expanded (each call site costs its callee, each function weighed once, depth first with a memo, so the analysis is linear whatever order the module's functions are in): every value weighs its size in 16-byte units, at least 1, texture samples 16 more, other image accesses 4, atomics 8, derivatives 4; at most 2^14. A call tree of doublings is refused by this, not run. |
| Memory traffic per invocation | Loading, storing, composing, selecting, passing or returning a value moves all of it, and weighs its size in the cost above; one value larger than an invocation's memory (16 KiB, such as a whole storage array assigned at once) is refused. |
| GPU time per pass | At most 2^16 invocations; cost × invocations × (loop cap + 1) at most 2^25 weighted operations (about half a millisecond of light work on an M1 Max), the loop cap chosen to fit and the pass refused if fewer than 64 iterations would be left; measured where timestamps exist, a pass over 1 ms in 3 of its last 8 timed frames is turned off. |
| GPU time per frame | A frame runs at most 2^27 of sandboxed work (four passes' worth) and 2^26 of one owner's; passes past it wait their turn. An owner's passes over 2 ms together in 3 of 8 timed frames are all turned off. All passes share the frame's 2^26 invocations. |
| Passes | 64 sandboxed a world, 16 an owner (1,024 passes a world in all). |
| Synchronisation | A barrier, `workgroupUniformLoad` or subgroup operation inside a loop is refused: an invocation leaving the loop at its cap would leave the rest waiting. |
| Compile and validation time | At most 1 MiB of WGSL and 2^16 IR nodes, parsed and validated on the app's thread when added; the cost bound also bounds what a driver's inlining makes. Sandboxed pipelines compile on a worker of their own, so a driver stuck on one holds up none of the app's; a pass not compiled within 10 s fails and its worker is let go, a new one compiling the rest (other owners' passes waiting on the old are sent again); an owner whose shaders stalled drivers four times has no more compiled (others' still are), and after 32 stalls in all a process compiles no more sandboxed shaders, rather than leave stuck threads without end. |
| Memory | At most 16 KiB of private and function-local memory an invocation and 16 KiB of workgroup memory; buffers and textures it binds are the app's, under the world's memory cap. |
| Reads back | Through the app's readbacks: their budget and queue cap. |

`buffer.read(range)` and `texture.read()` copy what the GPU holds after a frame into a `Readback`, which resolves a few frames later (`try_take` each frame, or `.await` it). Reads go in the order asked, at most `set_readback_budget` bytes a frame (64 KiB to begin with), in chunks of their own; a larger one takes more frames, and none makes a frame wait for the GPU. A read whose `Readback` is dropped is let go, and reads queue up to 64 frames of the budget: one past that is refused (`ReadError::Busy`) unless nothing else is queued. Writes waiting for a frame merge where they meet, so they never hold more than the buffer.

## Particles

With the `particles` feature, `World::add_emitter` adds an `Emitter`: a pool of particles born where its `Spawn` says (`point`, `box_`, `sphere`, or `cone` along an axis) at a `rate` a second or in a `burst`, living a random time in their `lifetime`, moving from their `velocity` under their `force`s (`Gravity`, `Constant`, `Drag`, `Wind`, `Swirl`), colliding with a plane (`Collide::Plane`, bouncing, sticking or dying), and drawn as soft billboards or streaks along their motion, over what's behind them or adding light to it, their colour and size changing over their life.

```rust,ignore
let rain = world.add_emitter(
    Emitter::new(200_000)
        .spawn(Spawn::box_([-40., 30., -40.], [40., 32., 40.]).rate(60_000.))
        .lifetime(0.6..0.9)
        .velocity([0., -22., 0.], 1.5)
        .force(Force::Gravity)
        .force(Force::Wind([2., 0., 1.]))
        .force(Force::Drag(0.1))
        .collide(Collide::Plane { height: 0., then: Response::Die })
        .draw(Shape::Streak { length: 0.04 }, Blend::Alpha)
        .size(0.01..0.015)
        .color([0.7, 0.75, 0.8, 0.5]),
)?;
world.set_emitting(rain, false); // what has fallen finishes falling
```

An emitter can give birth to another's particles where its own die or collide: `Emitter::on_death(child, count)` and `on_hit(child, count)`, `child` an emitter already in the world whose spawn shape is placed at the event (splashes where rain lands, sparks where they bounce). A sub-emitter is born into by its parents alone, and settles once their particles can no longer die or hit and its own have lived out their lives.

A pool holds `Emitter::new`'s count at once; a full one replaces its oldest. `add_emitter` refuses a pool larger than one storage binding and one dispatch hold on the view's device (`EmitterError::TooMany`: 1,677,721 particles on WebGPU's default limits; more rain is more emitters), and counts pools with the app's buffers and textures under the world's memory cap. Particles are updated by a compute pass, or on the CPU where the device runs none (`caps().compute` false), at most `CPU_PARTICLES` (16,384) an emitter and `CPU_WORLD_PARTICLES` (65,536) a world: past it, in the order added, an emitter waits, neither stepped nor drawn, and `World::emitter_status` says so (`OverCpuParticles`). A scene built before its first frame, when the device isn't known yet, is held to it as it draws. A world draws while an emitter emits or any of its particles may live, then settles: a burst that's over lets it go idle. `World::burst` spawns more at once and `move_emitter` moves where it spawns. `World::set_emitter` (or `set_emitter_rate`, `_spawn`, `_lifetime`, `_velocity`, `_forces`, `_color`, `_color_over_life`, `_size`, `_size_over_life`) changes an emitter from its next update, its particles living on; a new `max` makes its pool again, checked as `add_emitter` checks one.

`particles_bench` measures their GPU time at 1080p against a world without them. Particles are drawn in front of the meshes for now; drawing them against the scene's depth (and soft where they meet it) comes with the renderer's pass list.
## Custom materials

With the `shaders` feature, a mesh can be drawn by WGSL functions of the app's own, plugged into the lit pipeline: shadows, lights, the environment and tone mapping keep working around them. A `MaterialShader` is text whose first line is `#zgx material 1`, with any of three functions:

**Custom materials are trusted code.** A shader runs for every vertex and pixel of its meshes with nothing bounding its loops: one that never ends holds the GPU every window shares. Give `add_shader` only what the app itself wrote or vetted; plugins and scripts get no way to reach it until a sandboxed mode exists.

```rust,ignore
let water = world.add_shader(
    MaterialShader::new(include_str!("water.wgsl"))
        .param("deep", Param::Color)       // params.deep in its WGSL
        .param("foam", Param::Texture)     // params.foam, sampled with material_sampler
        .reads_scene()                     // it calls scene_color
        .animated(),                       // it reads frame.time
)?;
world.set_shader(mesh, Some(water));
world.set_param(water, "deep", [0.0, 0.2, 0.3, 1.0])?;
```

```wgsl
#zgx material 1
// Vertex stage, and the shadow pass: where its vertices are.
fn displace(v: VertexIn) -> Displaced {
    var d: Displaced;
    d.position = v.position + v.normal * 0.05 * sin(v.world.x * 4.0 + frame.time);
    d.normal = v.normal;
    return d;
}
// Fragment stage: what the lit pipeline shades.
fn surface(s: SurfaceIn) -> Surface {
    var m = surface_default(s);               // what its Material and maps give
    let behind = scene_color(s.screen_uv, 2.0);
    m.base_color = mix(behind, params.deep.rgb, 0.6);
    m.roughness = 0.05;
    return m;
}
// Cut-outs, in the main and the shadow pass: under the mesh's alpha cutoff
// (a half if it has none), the fragment isn't there.
fn opacity(s: SurfaceIn) -> f32 { return 1.0; }
```

`World::add_shader` reads and compiles the text when it's called, not when a frame first draws it, and returns a `ShaderError` at the app's own line and column (the engine's lines are not counted). A shader's top-level names are its own: it may name a function `shade` or a constant `PI` without meeting the engine's, or another shader's.

What only the device can refuse (more textures in a stage than it binds, with a mesh's own maps, glass and coat) is caught as a frame compiles or binds the shader, never stopping it: the mesh draws as without its shader, and `World::shader_error(id)` says why. A world takes shaders of at most 256 KiB of text, 64 parameters (names of 64 bytes), four textures each, 1,024 shaders and 8 surface layers; a shader past any of these is refused when added.

A shader's pipelines compile off the frame, on a thread of their own, the first time a mesh using it is in a frame (in view or not). Until they're ready its meshes draw by the plain pipeline, in their material's colour; where that can't stand in (a world lit by an environment, clusters, cascades or probes) they aren't drawn, so a heavy shader's first appearance pops in. To avoid it, add the mesh where the camera doesn't see it (or before it's shown) and show it once `World::shader_ready(id)` says its pipelines are in.

With the `compute` feature too, a parameter can be an app's GPU data: `.buffer("waves", "array<vec4<f32>>")` reads a `GpuBuffer` (`World::add_buffer`) as `params.waves`, a `var<storage, read>` of that type, and `.param("height", Param::GpuTexture)` a `GpuTexture` (`World::add_texture`, any float format) as a `texture_2d<f32>` read with `textureLoad`. `World::set_param(shader, "waves", &buffer)` binds it; a compute pass writing it each frame feeds the material, and its meshes draw from the new contents with nothing else to do. Until its data is on the device a buffer reads zeros and a texture black. A shader reads four of them at most.

A shader whose `displace` moves vertices says how far with `.displaces_by(metres)`: its meshes' boxes grow by that for culling and for the sun's shadow and cascades' fit. A displacing shader that doesn't say is never culled (so it can't vanish), and what it moves past its mesh's box may fall outside the sun's shadow.

`World::add_surface_layer(shader)` runs a shader's `surface` after every lit mesh's own, `surface_default` giving what that made: rain making everything wet, without touching each mesh. Layers run in the order added; their parameters are numbers (1 KiB in all). A world with no layer compiles none of this.

### The inputs of `#zgx material 1`

| Name | What |
| --- | --- |
| `frame.time`, `frame.delta`, `frame.index` | Seconds since the world's first frame, since the last, and frames drawn (`u32`). Only in a shader marked `.animated()`. |
| `frame.camera` (`.xyz`), `frame.view`, `frame.projection`, `frame.size` | The camera's position, its view and projection matrices, the target's size in pixels |
| `VertexIn`: `position`, `normal`, `uv`, `uv1`, `color`, `world` | The vertex in its object's space (after skinning and morphing), its coordinates (the second, or the first where it has none), its vertex colour (white without), its place in the world |
| `Displaced`: `position`, `normal` | What `displace` returns, in object space |
| `SurfaceIn`: `world_position`, `normal`, `geometric_normal`, `uv`, `uv1`, `color`, `view`, `depth`, `screen_uv`, `front_facing` | The fragment: its normal after the normal map and its face's, facing the camera; the mesh's colour (its material's times its vertex colour); the direction to the camera; its depth from the camera in metres; where on the target, 0 to 1 |
| `Surface`: `base_color`, `metallic`, `roughness`, `normal`, `emissive`, `occlusion`, `opacity` | What the lit pipeline shades. Make one with `surface_default(s)` and change its fields, never by its constructor: fields are added. `opacity` blends a translucent mesh (its `Material`'s alpha under 1). |
| `scene_color(uv, lod)` | The opaque scene behind the mesh as displayed, in linear light, blurred by mip level `lod`. Only in a shader marked `.reads_scene()`. |
| `params.<name>` | Its parameters: `f32`, `vec2<f32>`, `vec3<f32>`, `vec4<f32>` (a colour is linear RGBA), or a `texture_2d<f32>` (four at most) to sample with `material_sampler` |
| `surface_default(s)`, `noise2(p)`, `noise3(p)`, `hash(p)` | The surface so far; smooth value noise in [0, 1], one cell a unit; a number in [0, 1) for each point |

**The promise:** the names and meanings above. Within version 1 fields and helpers are added, never removed or redefined; a change that must break them is `#zgx material 2`, and a version this zgx doesn't read is an error naming it. In 0.x a minor release may make that change, with a changelog entry. Not promised: bind group numbers, the engine's own uniforms and functions (`frame.view_projection`, `shade`, …), or anything else a shader can reach. A shader that uses them may break in any release.

**What it costs:** a mesh without a shader, in a world without layers, draws as it did: its pipeline, binding and frame are the same, and the frame's check of each run doesn't look at shaders unless the stock pipelines have none for it. A mesh with a shader is drawn in runs of its own (a pipeline a shader and variant), and a frame writes a shader's numbers only when they changed. Without the `shaders` feature none of it is built.

**Not yet:** `scene_depth` (it comes with the depth prepass); `VertexIn.instance` and `SurfaceIn.instance` (per-instance numbers); buffer parameters (with compute passes); textures in surface layers. A shader that moves its mesh by time moves its shadow on frames that draw the shadow map again (a change to the world's meshes), not on every frame it animates. A mesh moved out of view while culling rests (up to 15 frames) keeps an animated world drawing until the next change to its meshes.

## Bounced light

With the `gi` feature, `World::add_probes(ProbeVolume::new(min, max, [x, y, z]))` fills a box with a grid of irradiance probes: each records the light arriving at its point from every direction, including light bounced off the scene and the sky, and how far away the surfaces around it are. Lit meshes inside the box then take their diffuse light from the eight probes around each pixel instead of from the hemisphere or environment: a white wall beside a red one turns pink, and a face the lamp can't see is lit by the floor. The distances keep light from leaking through walls.

Probes are filled by tracing rays, so the device has to support ray queries: call `zgx_gpu::request_ray_queries()` before the first window is made. It's `unsafe`: it turns on wgpu's experimental ray queries for the whole process, and wgpu says an experimental feature may have bugs reachable from safe code, which the app takes on in its own `unsafe` block. `World::probes_status()` says what the last frame did with the probes: `Traced`, or why not. `NoRayQueries` means the device can't trace (`zgx_gpu::ray_queries_status()` says why); a volume then does nothing and meshes are lit as without it. Probes work beside the `lighting` feature's clustered lights and sun cascades. `World::probes_traced()` is `probes_status() == Traced`.

A world updates `per_frame` probes a frame (64 by default, `rays` each, 128 by default) until every probe has been updated 16 times since what rays see or what lights it last changed: a traced mesh moved or recoloured, a light changed, or the sun, sky or environment. Turning the camera, and changes to meshes rays don't see (a skinned mesh's pose, glass), change nothing here. A change shows within the first round; later rounds average out the noise and let light bounce more than once. Then the world settles and stops drawing. A world holds up to 4 volumes (`MAX_PROBE_VOLUMES`) and 8,192 probes in all (`MAX_PROBES`). Each probe costs 2.5 KB of texture (two Rgba16Float maps, 8 by 8 and 16 by 16).

What rays see: meshes in their material's colour and glow (textures aren't read), lit by the sun and every point and spot light within its range, with shadows (a ray to each light where there are eight or fewer; where more, to one picked by how much light it brings, which averages out over the rounds), and by the probes' own light. Lights' radii (the `lighting` feature's `PointLight::radius`) aren't read: rays see each light as a point. Skinned and morphing meshes, and meshes light passes through, are left out. Point lights cast no shadows on meshes drawn directly, so the probes' shadowed bounce light can differ from the direct light next to it.

```rust,ignore
// Needs the `gi` feature.
use zgx_3d::*;

// SAFETY: the app takes on wgpu's experimental contract for ray queries.
unsafe { zgx_gpu::request_ray_queries() }; // before the first window
let world = World::new();
let room = world.add_probes(ProbeVolume::new([-5., 0., -5.], [5., 3., 5.], [8, 4, 8]));
```

## Post

With the `post` feature, `World::set_post` turns on passes a frame goes through after its meshes. With any on, meshes draw in linear light into a float target of their own (unbounded, so highlights keep their brightness), and a last pass exposes and tone maps the scene and writes the view. Unlit meshes are exposed and mapped with the rest; the background shows as given. With none on, a world draws as it does without the feature.

`Bloom` spreads light around what is bright, as a lens's glare does: the scene is blurred wider and wider and mixed in by `intensity` (0.04 by default). It mixes rather than adds, so only what is much brighter than its surroundings glows, with no threshold to set.

`Vignette` darkens the corners as light through a lens falls off (cos⁴ of the angle off its axis), `Grain` adds film's grain in the middle tones after mapping, a function of the frame's index so a recorded frame repeats, and `ChromaticAberration` parts red outward and blue inward toward the edges. These three are part of the last pass, compiled in only when on.

`Grade` grades the colours: `temperature` and `tint` move the white point (in LMS, as the eye adapts) before the tones are mapped; `lift`, `gamma`, `gain` and `saturation` then act on what the display shows, and `lut` applies a 3D look-up table last, read with `Lut::from_cube` (a `.cube` file from a grading tool, sRGB in and out) or `Lut::from_strip` (a strip image, N tables of N by N side by side). The table is uploaded once to each device; tables in log space, applied before the tone curve, aren't read yet.

`AutoExposure` makes exposure follow the scene's light, as an eye or camera adapts: each frame a histogram of the scene's brightness is taken on the GPU, the mean of its middle (`low` to `high`, the brighter half less its brightest tenth by default) is brought to middle grey, and the exposure eases toward that at `up` stops a second for a brighter scene and `down` for a darker one, in the frame's own time. `World::set_exposure`'s stops apply on top as compensation. The world keeps drawing while it adapts and stops once it's within 1/64 stop. It needs compute (`World::caps`); elsewhere the stops alone apply.

`World::add_post` adds a pass of the app's own: WGSL beginning `#zgx post 1` that defines `fn post(p: PostIn) -> vec4<f32>`, run on every pixel. It reads the frame so far with `color(uv)`, `p.uv`, `p.size` and `p.position`, `frame.time`, `frame.delta` and `frame.index`, and `params.<name>` for each `param` it declares (set with `World::set_post_param`). `PostStage::Hdr` (the default) runs on the scene's linear light before exposure and bloom; `PostStage::Display` on what the display shows after mapping and grading. Passes of a stage run in the order added. A shader that doesn't compile is refused at `add_post` with its own line numbers. A pass reading `frame.time` is marked `animated()`, so its world keeps drawing while it's in. `depth(uv)` and `velocity(uv)` come with the depth prepass.

```rust,no_run
use zgx_3d::*;

let world = World::new();
let pass = world
    .add_post(
        PostPass::new("#zgx post 1
fn post(p: PostIn) -> vec4<f32> {
    let c = color(p.uv);
    return vec4(c.rgb * params.strength, c.a);
}")
        .param("strength", PostParam::Float),
    )
    .expect("a valid pass");
world.set_post_param(pass, "strength", 1.5).unwrap();
```

With the chain on, a pixel's samples are resolved by the chain itself, each weighted by what the tone curve will make of it, so the edge of a highlight against a dim surface is as smooth as without the chain (averaging bright samples in linear light first would stair-step it).

What it costs: the scene's 8 bytes a pixel, bloom's steps (from half the size: a sixth of that where the GPU draws into three packed floats, as Apple's and most desktop GPUs do, else a third), and, with multisampling, the samples' colour at 8 bytes each instead of 4: about 33 MB more than without the chain at 1920 by 1080, 133 MB at 4K. The background, plain or transparent, keeps an alpha channel so it can show as given (unexposed and unbloomed); worlds with a sky will draw their scene in 4 bytes a sample. Temporal antialiasing, when it comes, has no multisampled colour and removes this cost. Like the other targets they go when the window rests.

```rust,no_run
use zgx_3d::*;

let world = World::new();
world.set_post(Post {
    bloom: Some(Bloom { intensity: 0.06 }),
    vignette: Some(Vignette::default()),
    grade: Some(Grade {
        temperature: 0.2,
        saturation: 1.1,
        ..Default::default()
    }),
    ..Default::default()
});
```

## Picking

`World::pick(point, size)` says what a point of the view's box shows: a `Hit` with the `object`, the `point` on it in the world and its `distance` from the camera. It's found on the CPU from the meshes' triangles, so a world never picked costs nothing.

```rust,no_run
use zgx_3d::*;

fn clicked(world: &World, x: f32, y: f32, width: f32, height: f32) -> Option<ObjectId> {
    world.pick((x, y), (width, height)).map(|hit| hit.object)
}
```
